### Penyimpangan dari plan

- KTD-G6 menyebut kolom `decided_verdict`. Tidak perlu: Skipped selalu berasal dari Fail dan Checked manually dari Can't verify. Review run grup memakai `reset_for_group_review`, yang mempertahankan alasan dan pemutus di baris buku AC; `restore_decisions` di akhir review memulihkan keputusan bila verdict sama dan membuangnya bila berubah. Tool `ac_set_verdict` tidak lagi mengosongkan alasan/pemutus; run tunggal tidak terpengaruh karena `reset_for_review` sudah mengosongkannya saat review dimulai.
- Test U7 ada di `tests/group_flow.rs` (bukan `tests/waiting_fix.rs`) agar memakai helper grup yang sama.
- Run lanjutan setelah PR grup merged hanya memakai repo utama run grup. Perubahan perbaikan yang belum di-commit di worktree grup dibiarkan (PR grup sudah merged).
- Revert kartu di workspace dengan commit di beberapa repo: bila revert di repo kedua konflik, revert di repo pertama tidak dibatalkan (port git tidak punya reset). Gerbang tetap tertahan dengan "revert conflict"; dev menyelesaikannya di branch atau memilih tetap. Kasus ini jarang karena satu kartu biasanya menyentuh satu repo.
- `AcRowView` membawa `card` berupa `record_id`, bukan kunci kartu; UI memetakan ke kunci lewat `RunView.cards` (menghindari pembacaan cache per baris di `ledger.get`).
- Test daemon sungguhan untuk method grup hanya bisa memeriksa tanpa sesi Lark (dikenal dan butuh sesi, beda dari method tak dikenal); tampilan papan grup diuji di unit test `views.rs`.
- `StartGroupDialog` tidak dibuat terpisah: "Start together" menjadi bagian dialog Start (`GroupCardPicker`) agar pilihan repo, workspace, planning, dan review tidak diduplikasi. Keputusan kartu berubah memakai `ChangedCardsDialog` baru, bukan `GateDialogs`.
