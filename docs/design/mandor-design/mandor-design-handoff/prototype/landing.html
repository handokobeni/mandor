Run a crew of Claude Code agents from one board.

Mandor puts every agent on a kanban board that stays in sync with Lark Base, both ways. Each agent works in its own git worktree, opens a PR, and never merges to main. You see who is working, who is waiting for you, and what broke.

Needs your own Claude Code subscription, a Lark Custom App with a Sprint Tasks base, and the GitHub CLI.

The problem

Six terminals. Which one is waiting for you?

Running agents in parallel works until you lose track. One terminal per task, one task per Lark record, and nothing tells you which session finished its turn twenty minutes ago. Then the Lark board drifts, because someone has to copy every status by hand.

… Lark still says "To Do"

How it works

The board is the foreman. You stay the reviewer.

  1. 01

    Press Start on a ready task

    Mandor claims the Lark record, creates a worktree from origin, and starts Claude Code with the title, description, and acceptance criteria. Lark moves to In Progress.

  2. 02

    Every agent in one sidebar

    Working, waiting for you, failed, or parked. Runs that need your reply are pinned to the top, with a count in the title bar and the tray.

  3. 03

    Push & create PR

    When the diff looks right, one button commits, pushes the branch, and opens the PR. Lark moves to Waiting Review. Merging stays with your team.

  4. 04

    Review fixes come back on their own

    A reviewer moves the task to Waiting Fix and comments in Lark. Mandor forwards trusted comments, the agent fixes, and the task returns to review.

Two-way Lark sync

Lark stays the source of truth.

Columns come from Task Status, not a second board. Titles, descriptions, acceptance criteria, and assignees are read from Lark and never edited by Mandor. When Lark and Mandor disagree, Lark wins and the card says so.

  • Only three automatic moves: To Do → In Progress, In Progress → Waiting Review, Waiting Fix → In Progress
  • Starts only tasks marked Ready To Dev or Commit To Sprint
  • One owner per task. If two people press Start, one gets a clear "lost the claim"

The review loop

"Waiting Fix" no longer waits for you.

Reviewers keep working the way they do today: change the status in Lark and leave a comment on the record. Mandor handles the rest, and asks you only when a comment comes from someone it should not trust.

  1. Reviewer comments in Lark

    The task moves to Waiting Fix with a comment on the record.

  2. Quiet period

    Mandor waits about two minutes so the reviewer can finish writing.

  3. Trusted comments forwarded

    From assignees, the reporter, and the reviewers you list per repo. Others are shown to you only.

  4. Fixing

    The agent applies the feedback in the same worktree and pushes to the same PR.

  5. Back to Waiting Review

    Lark is updated. Nobody had to open a terminal.

Safety

Agents write code. They don't ship it.

  • One worktree per task. Agents never touch your checkout or each other's branches.
  • No merges to main, ever. Mandor opens PRs; your team decides what lands.
  • git push belongs to Mandor. The agent's own push is denied; pushing happens through Push & create PR.
  • Sensitive files are held. Changes to CI, agent config, or git hooks wait for your confirmation before any push.
  • Lark text is data, not instructions. Titles, AC, and comments reach the agent as untrusted content.

What you need

Bring your own tools. Mandor brings the board.

Claude Code, your subscription

Mandor runs the Claude Code CLI as it is, logged in with your own subscription. No API key, no resold usage.

Lark Custom App + Base

A Custom App with access to your Sprint Tasks table and its Acceptance Criteria table. You log in with Lark once.

Linux, or Windows with WSL

The daemon runs on Linux or inside WSL on Windows. macOS is not supported yet.

FAQ

Questions developers ask first.

Does Mandor need an Anthropic API key?

No. Mandor starts the Claude Code CLI unmodified, using the subscription you are already logged in with.

Will an agent ever merge to main?

No. Each task gets its own branch and worktree. Mandor pushes that branch and opens a PR. Merging is always a person on your team.

Can I drag cards between columns?

No, on purpose. Columns follow Task Status in Lark. Cards move when you press Start or Push & create PR, or when someone changes the status in Lark.

What if two developers start the same task?

One claim wins. The other person sees "lost the claim" and nothing is created on their machine. An inactive claim can be taken over later.

Does it run on macOS or native Windows?

Not yet. Today the daemon runs on Linux, or inside WSL on Windows. Other platforms are not verified.

Where does my code go?

Agents run on your machine, in worktrees next to your repo. Code goes where Claude Code itself sends it, and to GitHub when you push.

Is Mandor affiliated with Anthropic, Lark, or GitHub?

No. Mandor is an independent tool that works with Claude Code, Lark Base, and the GitHub CLI.
