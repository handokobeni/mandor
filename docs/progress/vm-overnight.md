### Penyimpangan dari plan

- Klaim lama tanpa id daemon: plan (KTD-55) menyebutnya milik daemon tak dikenal. Daemon **laptop** menganggap klaim lama atas `open_id`-nya sebagai miliknya dan mengadopsinya (nonce baru dengan id daemon) pada heartbeat berikutnya, agar run yang berjalan sebelum upgrade tidak kehilangan klaim. Daemon **VM** mengikuti plan: klaim lama ditolak sampai basi.
- Penolakan link VM untuk daemon laptop yang belum mendukung klaim per daemon (dari versi protokol `hello`) dikerjakan bersama koneksi SSH (U9).
- Penjadwal ditulis sebagai blok `impl RunService` di modul `overnight` (seperti `waiting_fix`), bukan `OvernightService` terpisah; port antrean ikut di `RunPorts`.
- Migrasi lembur bernomor `0007` karena `0006` sudah dipakai `run_cards` (plan run grup).
- "Agent buntu" di VM dideteksi sebagai giliran implementasi yang berakhir tanpa perubahan kode; teks akhir agent disimpan sebagai pertanyaan.
- Run grup di VM tetap memakai alur laptop sampai U10 plan run grup.
- Login Claude diperiksa saat penjadwal akan memulai kartu (bukan di awal siklus) agar tidak menjalankan `claude auth status` setiap tick.
- Isi laporan memakai keadaan kartu VM yang masih menunggu dev saat jam lembur berakhir (PR draft, tertahan per alasan, gagal) dan kartu yang dikeluarkan dari antrean sejak siklus mulai, bukan riwayat setiap run di siklus itu; riwayat lengkap per kartu ada di laporan tab Overnight (U10).
- Kolom `report_attempts` ditambahkan ke migrasi `0007` (belum pernah dirilis).
- Test serah-terima ada di `tests/handoff.rs` (plan menyebut `tests/ownership.rs`, yang belum ada di repo).
- Penjaga konfigurasi git KTD-65 hanya aktif di daemon VM; daemon laptop tetap seperti Rilis 1 karena pengguna laptop bisa bergantung pada konfigurasi sistem git (mis. credential helper).
- `GIT_CONFIG_GLOBAL` agent menunjuk ke `<run dir>/gitconfig`; bila berkas itu tidak ada git memperlakukannya kosong. Identitas commit agent tidak diperlukan karena commit dilakukan daemon.
- KTD-65 (perbaikan review keamanan U6): penjaga konfigurasi git VM memakai allowlist kunci lokal/worktree (bukan denylist), gagal-tertutup bila konfigurasi tidak terbaca, dan setiap proses git daemon VM (termasuk lewat `gh`) mendapat override `GIT_CONFIG_PARAMETERS` yang menetralkan kunci pengeksekusi (`core.sshCommand`, `credential.helper`, `protocol.ext.allow`, dll.). Sisa celah: `include.*`, `url.*`, dan `filter.*` yang ditambahkan agent sesudah pemeriksaan tidak bisa dinetralkan lewat override; ditutup dengan izin berkas (direktori `.git` repo tidak bisa ditulis user agent), yang diperiksa penjaga U11 dan runbook.
- KTD-65 (review keamanan kedua): allowlist dipersempit per kunci (`fetch.prune`, `pull.rebase`, `extensions.worktreeconfig`/`objectformat`; `init.*` dan submodule ditolak) dan override menambah `core.hooksPath` (berlaku juga untuk git yang dijalankan `gh`), `commit.gpgSign`/`tag.gpgSign=false`, `fetch.recurseSubmodules`/`submodule.recurse=false`. **Risiko terbuka untuk dibahas sebelum U12:** KTD-62 menaruh clone dan worktree di direktori grup yang bisa ditulis agent, sehingga agent bisa mengubah `.git/config` (atau berkas `.git` worktree) di antara pemeriksaan dan perintah git daemon; kunci bersubseksi (`include.*`, `url.*`, `filter.*`, `remote.*.url`) tidak bisa dinetralkan lewat override. Penutup penuhnya mengubah desain: direktori git (clone utama dan `worktrees/`) milik user daemon dan tidak bisa ditulis agent, atau git daemon memakai `GIT_DIR` eksplisit milik daemon.
- U7: biner Playwright MCP dikonfigurasi lewat `MANDOR_PLAYWRIGHT_MCP` (path absolut) karena agent berjalan dengan `PATH` allowlist; pemasangan `@playwright/mcp` dan `npx playwright install chromium` di user agent dicatat untuk runbook `setup-vm.md` (U12). Pagar tab per-tab seperti Claude in Chrome tidak diperlukan karena browser Playwright sendiri memblokir permintaan ke origin lain; hook tetap memeriksa URL navigasi.

### Temuan dan perbaikan

1. **Check host key gagal lewat IAP**: `ssh-keyscan` tidak memakai `ProxyCommand`. Scan kini lewat `ssh` dengan config pengguna di direktori sementara privat (`617670e`, `032697d`).
2. **System check: `claude` tidak ditemukan** di PATH service systemd. Cek login dan system check memakai PATH login shell (`2a15be1`).
3. **`git fetch` ditolak** untuk repo tanpa gh profile (credential helper dinonaktifkan KTD-65): pakai akun `gh` aktif (`3c44073`). Lalu **token gh tersensor**: `mandor_proc::run` meredaksi stdout, sehingga `gh auth token` menjadi `ghp_[REDACTED]`. Ditambah `run_secret` (`3505b0e`).
4. **App tidak dinyalakan sebelum review headless**: restart otomatis hanya untuk app yang sudah menyala. Di VM app yang belum menyala dinyalakan (`ef16175`), dan app kartu sebelumnya dihentikan karena kartu lembur berurutan (`8fef0b8`, disetujui pemilik produk).
5. **Deskripsi PR gagal ("external diff died")**: override `diff.external=` kosong membuat git menjalankan program "". Override dibuang, semua `git diff` daemon memakai `--no-ext-diff` (`9d06eaa`).
6. **Loop review tanpa batas (34 review pada PGS-1521)**: Playwright MCP menulis snapshot ke `.playwright-mcp/` di worktree, sehingga setiap review basi dan gerbang memulai review baru. Output Playwright kini di `<run dir>/playwright/<review>`, dan review basi di VM menahan kartu `ac_gate` alih-alih review ulang (`1c0b5c3`).
7. **Batas pemakaian tidak menghentikan loop**: batas hanya menghitung input + output, padahal hampir semua input Claude Code masuk cache (34 review tercatat sekitar 4 ribu token). Batas kini menghitung cache tulis penuh dan 10% cache baca; KTD-59 direvisi (`864e29d`, disetujui pemilik produk).
8. **Kartu `ac_gate` dengan review putus tidak bisa diputuskan**: "action not available (held)". Di VM keputusan dev kini memulai review headless baru (`bac8534`).
9. **Hook review menolak klik setelah `browser_fill_form`**: Playwright MCP 0.0.83 tidak menyertakan `Page URL` di respons `fill_form`, dan hook menganggap alamat tidak diketahui. Isi form yang berhasil tanpa baris URL kini mempertahankan alamat (halaman tetap belum stabil sampai `wait_for` dengan URL baru); tool lain tetap gagal-tertutup (`129b642`, dipersempit setelah review keamanan di `6f23409`).
10. UI tab Overnight dan Settings VM: halaman tidak lagi Loading terus saat VM belum login Lark (`81d7466`); pemilih antrean terbaca, bisa dicari, dan tidak melebar (`717e81e`, `24ccfb2`, `050b4f1`, `c056799`); judul laporan satu baris (`f9cec35`); jam lembur dan offset UTC dipilih dari daftar (`a1baae7`).
